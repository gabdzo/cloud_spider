# Services and routes

Follow one direction, and do not skip a layer because a higher layer exists.

1. Route. `oc get route -o yaml` shows host, path, the service name, and `targetPort`. Admitted routes can still serve the application-unavailable page. That page is generated by the router when it has no backend, not by your pod.
2. Service. The selector must equal the pod labels. `targetPort` must be the container port or a named port on the pod, not the service port. Those are different fields.
3. Endpoints or EndpointSlice. An empty address list means no ready pod matched. A populated list means the router or kube-proxy has somewhere to send packets. It does not prove the port inside the container is the right one.
4. Pod. `Ready` depends on the readiness probe. A running container with a failing probe is absent from endpoints.

Path routes on one hostname are two Route objects. The longer path wins. The request URI is forwarded as-is unless the application or the router rewrites it. This lab's API process expects `/api/`.

`oc describe service` shows the selector and the endpoints together. When the endpoints line is empty, compare selector and `oc get pods --show-labels` before changing the route.
