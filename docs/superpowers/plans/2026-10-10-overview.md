### Upgrades

An upgrade is a small Pulumi module that creates one resource family, with fields you can type. Each module lists its parameters (name, type, default). The screen renders those fields. The local process passes them as Pulumi config. There is no free-form shell string.

These modules are not folded into `infra/index.js`. That stack is the test VPC you destroy. A module that spins up something on a cluster should be its own program so a destroy of the test stack does not take the upgrade with it, and an upgrade does not quietly grow the test stack.

Where it runs is still open. Do not pick it in this review.

| Choice | What happens |
|---|---|
| Laptop | The same process that holds your keys runs `pulumi up` with the typed parameters. A mistake spends money on this account. The $10 alert is still unprobed. |
| A worker | The page submits the parameter set. Something else runs Pulumi. The cluster has to exist first, and the keys live somewhere that is not the laptop. |
| Preview only | The laptop runs `pulumi preview` and does not apply, until the budget alert exists. |
